## 方法六：生意经「右上角切换商户」快速切户（用户截图教学，2026-07-22）

### 背景
此前已记录三种进入目标商户生意经的方式：
1. 来客首页 → 切换商户弹窗（方法二）
2. 林客商家概览 → 商家后台按钮跳转（方法四）
3. 生意经 URL 带 `?groupid=XXX` 直接打开

但**在已经进入某商户的生意经后、想切换到另一商户时**，最快捷的方式是：**生意经页面右上角直接点「切换商户」**。

### 完整路径（用户截图确认）
1. 已进入任意商户的 **生意经** (`life-data.cn`)
2. 页面 **右上角** 显示当前商户全称（如「湛河源莲花湿地」）
3. 商户名下方弹出面板，包含：
   - 账户ID
   - 手机号
   - **「切换商户」** 按钮 ← 红色箭头标注
   - 退出登录
4. 点击 **「切换商户」** → 弹出商户选择对话框 → 搜索/选择目标商户 → 确认
5. 页面刷新后即进入目标商户的生意经数据中心

### 与其他切换方式对比

| 维度 | 方法二（来客内切换） | 方法四（林客跳转） | **方法六（生意经内切换）** |
|------|-------------------|-------------------|--------------------------|
| 入口 | 来客首页右上角 | 林客商家概览操作列 | **生意经右上角** |
| 前提 | 在来客首页 | 在林客商家概览 | **已在生意经中** |
| 适用场景 | 从来客开始 | 从林客开始 | **已在生意经、想换户** |
| 步骤数 | 4步（搜索→选中→确认） | 1步（点商家后台） | **2步（点切换→选商户）** |

### 自动化脚本参考
```bash
AB="…agent-browser.js"; export CHROME_PATH="…/msedge.exe"
# 前置：已在生意经页面（任意商户）

# ① snapshot 找到右上角「切换商户」
$AB snapshot | grep -n "切换商户"
# ② click 切换商户按钮
$AB click <切换商户ref>
sleep 2
# ③ 弹出商户选择对话框 → 搜索框输入目标商户
$AB snapshot | grep -n "textbox"
$AB fill <搜索框ref> "新海府"
sleep 1.5
# ④ 选中 + 确认
$AB snapshot | grep -n "海口琼山王树群新海府粥城"
$AB click <列表项ref>
sleep 1
$AB snapshot | grep -n '"确认"'
$AB click <确认ref>
sleep 3
# ⑤ 验证：URL groupid 变更 / 右上角商户名变更
```

### 注意
- **这是在生意经内部切换的最快方式**，不需要离开生意经页面。
- 切换后所有模块（经营/流量/投放等）自动跟随新商户，无需重设 URL。
- 用户截图时当前商户为「湛河源莲花湿地」（groupid=1733602871390221），右上角面板清晰可见「切换商户」入口。

## 方法五：林客商家概览「搜索框」快速定位客户（用户截图教学，2026-07-22）

### 背景
此前 agent 在林客商家概览页找客户时**逐行翻表格 + grep 名称文本**，效率低且容易看错行（曾把莲花湿地当成新海府点进去）。用户发截图指出：**右上角有搜索框，可以直接输入名称模糊查找**。

### 完整路径
1. 登录 **抖音林客** → 左侧菜单 → **「商家运营」** → **「商家概览」**
2. 页面右上角有搜索框，placeholder 文本：**"支持查找商家ID/名称/品牌名"**
3. 在搜索框输入关键词（支持模糊匹配）→ 表格自动过滤出匹配商户
4. 找到目标行后点「操作」列的 **「商家后台」** → 一键跳转来客

### 已确认的客户名称映射（用户逐一确认）
| 俗称 | 林客商家概览显示全称 | groupid |
|------|---------------------|---------|
| 漫萌萌 | **郑州爪哇岛商贸有限公司** | 1776747848611853 |
| 新海府 | 海口琼山王树群新海府粥城 | 1736233383495694 |
| 风之谷 | 福建语峰餐饮管理有限公司（风之谷大龙湖峡谷漂流） | 1820835356761163 |

### 自动化脚本参考
```bash
AB="…agent-browser.js"; export CHROME_PATH="…/msedge.exe"
# 前置：已在林客商家概览页面

# ① snapshot 找到搜索框 ref
$AB snapshot | grep -i "支持查找\|textbox.*search\|搜索"
# 或直接找 placeholder 含"查找"的 textbox
# ② fill 输入客户名（模糊即可）
$AB fill <搜索框ref> "漫萌萌"
sleep 1.5
# ③ snapshot 确认过滤结果只剩目标客户
$AB snapshot | grep -n "郑州爪哇岛"
# ④ 点该行的「商家后台」按钮
$AB snapshot | grep -n "商家后台"
$AB click <目标行商家后台ref>
```

### 注意
- **先搜再点，不要逐行肉眼核对**——之前因此点错过（莲花湿地≠新海府）。
- 搜索结果可能有多条（如搜"漫萌萌"应只出1条），snapshot 确认唯一后再点。
- 用户原话提醒："漫萌萌的后台名称是**郑州爪哇岛商贸有限公司**"（注意是**爪哇岛**不是"爪娃岛"）。

## 防遗忘清单（用户要求"不要忘记我教你的每一个技能"）

### 背景（为何要记）
此前 agent 多次尝试点开生意经自定义日历均失败（点日期文本、`@eN` 父 div、`textbox` 都弹不出浮层），遂在 capabilities.md 写成"自动化点不开、需用户手动设"。**这是错误结论。**

用户发来两张截图并指出关键：
- **截图 1（流量概览）**：统计周期文本旁有个**日历小图标**，点击即弹出双月日历，直接点起止日即可选时间段。
- **截图 2（内容分析）**：右上角有「**自定义**」按钮，点击后弹出同样的双月日历。
- **用户原话**："鼠标指针位于自定义或者时间框的位置时，时间框会显示，这个时间我们点击开始日期和结束日期即可选择时间段。如果是跨月的话要先选择开始月份和日期，然后再选择结束月份和日期。"

### 实测可用的完整路径（以流量模块为例）
1. 顶部「统计周期」旁有日期文本 `2026-07-08 ～ 2026-07-14` + 紧邻的**日历图标**（clickable generic，如 `e42`）。**点这个图标**（不是点文本）。
2. 弹出快捷选项面板：`近7日` / `近30日` / `自然月` / **`自定义`**。点「自定义」（如 `e69`）。
3. **双月日历面板弹出**（DOM 中含 `2026年6月`、`2026年7月` 文本 + 各月日期格子）。
4. **关键突破**：日历面板的日期格子是真实 DOM 元素，**有 `@eN` ref 编号，可直接 `$AB click @eN`**。
   - 例：7 月 6 号 = `e79`、7 月 12 号 = `e85`（**ref 每次 snapshot 重新编号，须先 snapshot 再定位，勿硬编码**）。
5. 先点起始日 `e79`，再点结束日 `e85` → 周期文本变为 `2026-07-06 ～ 2026-07-12`。
6. 点面板底部的「**自定义**」**确认按钮**（区分于第 2 步的入口按钮；用 eval 找文本=`自定义` 且父级是 button/clickable 的元素点击）→ 数据刷新为该周期。

### 备用 eval 法（ref 不易读时，按"7月相邻 + 文本数字"定位日格）
```bash
AB="…agent-browser.js"; export CHROME_PATH="…/chrome.exe"
$AB eval "(()=>{
  var all=[].slice.call(document.querySelectorAll('*'));
  function dayCell(txt){
    return all.filter(e=>{
      var p=e.parentElement; if(!p) return false;
      var sib=[].slice.call(p.children);
      var hasJuly=sib.some(c=>c.textContent.trim()==='7月'||c.textContent.trim()==='2026年');
      return e.children.length===0 && e.textContent.trim()===txt && hasJuly;
    });
  }
  var s=dayCell('6')[0], e=dayCell('12')[0];
  if(s&&e){ s.click(); e.click(); return 'clicked 6~12'; }
  return 'notfound s='+(!!s)+' e='+(!!e);
})()"
sleep 1.5
# 再点确认按钮
$AB eval "(function(){var all=[].slice.call(document.querySelectorAll('*'));for(var i=0;i<all.length;i++){if(all[i].children.length===0&&all[i].textContent.trim()==='自定义'){var el=all[i];for(var j=0;j<5&&el;j++){el=el.parentElement;if(el&&(el.tagName==='BUTTON'||el.getAttribute('role')==='button'||(el.getAttribute('class')||'').indexOf('clickable')>=0||getComputedStyle(el).cursor==='pointer')){el.click();return 'confirmed';}}}}return 'notfound';})()"
```

### 周期 per-module 特性（重要，避免白读）
- 生意经各**一级模块**（经营概览 / 流量 / 人群 / 内容分析）的周期**相互独立**。
- 在某模块设好自定义周期后，**同模块下的子 tab**（如 流量 → 内容分析下的视频/直播/获客卡分析）**会继承该周期，无需重设**。
- 但切到**另一个一级模块**（如 流量 → 人群）周期会回退成默认近7日，需重设。
- 经营概览的日期是纯文本展示（无日历图标），其周期若要精确到周，可在该页用同样方式点开日历设（或依赖用户首次手动设后其他模块继承）。

### 经营概览「交易数据」小标签切换（用户截图教学，2026-07-27）
- 经营概览「核心数据」→「交易数据」区块下有三个小标签：**金额 / 券数 / 人数**。
- 默认显示「金额」，点击「券数」切换后显示 **成交券数 / 核销券数 / 退款券数**。
- 点击「人数」切换后显示 **成交人数 / 核销人数 / 退款人数**。
- **周期保持一致**：切换小标签不会改变已设的 7.20-7.26 周期，只是同一交易数据按不同口径展示。
- 自动化：用 `real_click` 点在「交易数据」区块内、文本为「券数」/「人数」的叶子元素即可。

### 跨月选择（用户特别叮嘱）
若起止跨月（如 6/28 ~ 7/12）：双月面板同时显示两月，**先点开始月的日格，再点结束月的日格**（先选开始月份和日期，再选结束月份和日期）。

### 验证成功的标准
页面周期文本变为目标区间（如 `2026-07-06 ～ 2026-07-12`），且模块数据随之刷新（对比数据、流量来源表口径变成本周）。

## 方法二：多商户「切换公司」切换（用户纠正"直接切换即可"）

### 背景（为何要记）
agent 初次遇到"新海府"时误判为"在另一个登录态、需换登录"，还为此向用户提问。
**用户原话纠正**："直接切换商户即可。"
实测确认：同一运营账号下挂多商户，无需换登录，用「切换公司」对话框搜索即可切换。

### 实测可用路径（两种入口都通）
- **入口 A（来客首页）**：右上角公司名（generic clickable）→ 下拉「切换商户」按钮 → 「切换公司」对话框（搜索框 + 商户列表）。
- **入口 B（账号区）**：右上角头像/账号区 → 弹出账号面板 → 「切换商户」→ 「切换公司」对话框。
- 在「切换公司」对话框搜索框输入目标商户（**支持模糊**，如"新海府"）→ 列表出现全称「海口琼山王树群新海府粥城」→ 点选 → 底部出现「确认」→ 点确认。

### 可靠脚本（eval 按文本点击绕过 ref 失效）
```bash
AB="…agent-browser.js"; export CHROME_PATH="…/chrome.exe"
# ① 点头像/账号区或公司名呼出菜单（按文本定位，勿硬编码 ref）
$AB eval "(function(){var all=[].slice.call(document.querySelectorAll('*'));for(var i=0;i<all.length;i++){var e=all[i];if(e.children.length===0&&e.textContent.trim()==='切换商户'){var el=e;for(var j=0;j<6&&el;j++){el=el.parentElement;if(el&&(el.tagName==='BUTTON'||el.getAttribute('role')==='button'||(el.getAttribute('class')||'').indexOf('clickable')>=0||getComputedStyle(el).cursor==='pointer')){el.click();return 'clicked 切换商户';}}return 'no-parent';}}return 'notfound';})()"
sleep 1.5
# ② 点「切换公司」打开对话框
$AB eval "(function(){var all=[].slice.call(document.querySelectorAll('*'));for(var i=0;i<all.length;i++){var e=all[i];if(e.children.length===0&&e.textContent.trim()==='切换公司'){var el=e;for(var j=0;j<6&&el;j++){el=el.parentElement;if(el&&(el.tagName==='BUTTON'||el.getAttribute('role')==='button'||(el.getAttribute('class')||'').indexOf('clickable')>=0||getComputedStyle(el).cursor==='pointer')){el.click();return 'clicked 切换公司';}}return 'no-parent';}}return 'notfound';})()"
sleep 2
# ③ 在搜索框输入商户名（模糊）
$AB snapshot | grep -n "textbox"        # 找搜索框 ref，如 e112
$AB fill e112 "新海府"
sleep 1.5
# ④ 选中列表项 → 底部出现「确认」
$AB snapshot | grep -n "海口琼山王树群新海府粥城"   # 找列表项 ref，如 e113
$AB click e113
sleep 1
# ⑤ 点「确认」
$AB snapshot | grep -n '"确认"'
$AB click <确认ref>
sleep 3
```

### 验证
`$AB eval "location.href"` → `groupid` 改变（新海府 = `1736233383495694`）；快照右上角商户名变更为目标全称。

### 注意
- 搜索框**模糊匹配**即可（"新海府"能过滤出全称"海口琼山王树群新海府粥城"）。
- 列表项需**先点选中（高亮）**后底部「确认」才出现/可点。
- 切换后页面完整刷新，须重新 `snapshot` 定位元素。
- **生意经与来客共用 groupid 体系**：在来客切到新海府后，生意经用 `?groupid=1736233383495694` 直接打开即自动进入该商户数据中心（无需在生意经内再切一次）。

## 方法三：人机补位协作约定（用户确立，2026-07-15）

> 核心原则（用户原话）：**"后续无法触达的按钮或者页面可以让我来操作，你再读取数据。"**

落地规则（详见 capabilities.md 第三节）：
1. agent 遇阻即停、不瞎猜 → 给出精确操作指引（哪个页面/入口/设什么值）。
2. 用户说"设好了 / 登录好了"后，agent 重新 `snapshot` 续跑。
3. 优先降级方案（如翻页快照解析兜底导出），不强求用户手动导出文件。

### 本约定下的真实边界（实测后修正）
| 环节 | 是否还需用户手动 | 说明 |
|------|------------------|------|
| 登录 / 续期会话 | ✅ 必须用户 | 不能输验证码；cookie 关 Chrome 即清 |
| 生意经「自定义」日历 | ❌ **已可自动化**（方法一） | 用户发截图教学后打通，不再需手动 |
| 切换商户 / 切换公司 | ❌ **已可自动化**（方法二） | 同账号多商户直接搜索切换 |
| 视频管理页日期 / 直播专业版日期框 | ✅ 仍受限 | 无自然月键 / 日期框只读，需用户手动或翻页解析 |
| 下载明细 / 导出按钮 | ✅ 仍受限 | 沙箱拦截 blob 下载，改翻页快照解析 |
| 滑块验证 / 风控 | ✅ 必须用户 | 平台风控自动化无法绕过 |

## 方法四：林客→来客「商家后台」一键跳转（用户发截图教学，2026-07-21 打通）

### 背景
此前 agent 进入商家来客后台的方式是：先在来客首页登录 → 顶部导航点「生意经」→ 弹出商户选择窗搜索切换。但用户指出，**从抖音林客平台可以直接一键跳转到目标商家的来客后台**，无需在来客内搜索切换。

### 完整路径（用户截图确认）
1. 登录 **抖音林客** (`life-partner.cn`)
2. 左侧菜单 → **「商家运营」** → **「商家概览」**
3. 页面展示 **所有下挂商户列表**，每行显示：商家头像+名称、经营数据、风险状态
4. 每行最右侧 **「操作」列** 有 **「商家后台」** 链接按钮（蓝色文字）
5. 点击目标商家的 **「商家后台」** → **新标签页自动打开该商家的来客后台**，URL 自动带入 `groupid`
6. 在来客页面点击顶部导航 **「生意经」** → 进入该商家的生意经数据中心

### 关键验证结果（2026-07-21 实测）
- 林客 URL: `https://www.life-partner.cn/vmok/op-merchant/merchant-list?source=menu&from_module=directly_enter&from_page=live_data`
- 跳转后来客 URL: `https://life.douyin.com/p/home?enter_from=service&groupid=<商家groupid>&root_life_account_id=<ID>`
- 本次测试：风之谷大龙湖峡谷漂流 → groupid=`1820835356761163`，生意经显示名为 **太湖梦华**
- 商户列表中可见的其他客户：福建语峰餐饮、**郑州爪哇岛商贸有限公司**、海口琼山王树群新海府粥城等

### 与旧方法对比

| 维度 | 旧方法（来客内切换） | 新方法（林客跳转） |
|------|-------------------|-------------------|
| 入口 | 来客首页 → 切换商户弹窗 | 林客商家概览 → 商家后台按钮 |
| 前提 | 必须已登录来客 | 必须已登录林客 |
| 操作步骤 | 搜索→选中→确认（4步） | 直接点按钮（1步） |
| 自动带 groupid | 需手动确认 | ✅ 自动带入 |
| 适用场景 | 已在来客内时 | 从林客开始操作时 |


## 方法七：周一用「近7天」按钮 = 上周（快捷复盘法，2026-07-27 用户口授）

### 背景
做「上周复盘」时，此前流程是：点「自定义」→ 弹双月日历 → 逐格点起止日（如 7/20~7/26）→ 确认。用户指出：**周一做上周复盘时，直接点「近7天」按钮即可，数据完全等同于自定义选出的"上周"，但省去选日期的麻烦。**

### 原理（为何仅周一成立）
- 生意经「近7天」= 截至**昨天**往前推 7 天（T+1 数据延迟）。
- 以周一 7/27 为例：点「近7天」→ 覆盖 **7/20(周一) ~ 7/26(周日)**，恰好是一个完整自然周（上周）。
- **非周一不成立**：周二点近7天会包含本周一（7/27），周三包含 7/26~7/27……数据混进本周，不再等于"上周"。

### 适用场景与边界
| 维度 | 说明 |
|------|------|
| 适用 | 周一做「上周（上个完整自然周）」复盘 |
| 不适用 | 周二~周日、或要任意历史周（如两周前）→ 必须走「自定义」逐格选起止日 |
| 周期独立 | 与其他预设一样，每个一级模块需各自点一次「近7天」（切模块回退默认，需重设；模块内子 tab 继承） |
| 对比基准 | 「近7天」的对比值 = 再往前 7 天（如 7/13~7/19），与自定义选 7/20~7/26 的对比口径一致 |

### 自动化参考（CDP real_click 点叶子文本）
```python
# 在目标一级模块下（经营/流量/人群/投放…），点文本为「近7天」的叶子 span
real_click(c, "(function(){var all=[].slice.call(document.querySelectorAll('*'));"
            "for(var i=0;i<all.length;i++){"
            "if(all[i].children.length===0 && all[i].textContent.trim()==='近7天'){return all[i];}}"
            "return null;})()")
```
（与切「自然月」同理；若模块默认已显示「近7天」则无需操作。）

### 注意
- **仅限周一**。其他日子误用「近7天」会污染上周口径，务必用「自定义」精确选周。
- 此前新海府周报（7.20-7.26）用「自定义」逐格选，结论与"周一近7天"等价；下次周一直接点「近7天」即可提速，不必再弹日历。

## 方法八：生意经日期选择决策树（用户截图教学，2026-08-06）

### 背景
此前日期选择分散在多个方法里：月度用「自然月」、周一只用「近7天」、跨月用「自定义」。用户通过三张截图一次性把规则讲清楚，要求 agent 以后做复盘时按这套决策树选日期，避免口径混乱。

### 决策树（务必按顺序判断）

```text
做什么复盘？
├── 月度复盘
│   └── 优先选「自然月」→ 在月份面板点选目标月份（如 2026年7月）
│       → 周期自动变为 2026-07-01 ～ 2026-07-31，对比周期 = 上个月
├── 周复盘
│   └── 今天是否周一？
│       ├── 是（周一）→ 直接点「近7天」
│       │   → 周期 = 上周一 ～ 上周日（完整自然周）
│       │   → 对比周期 = 再往前一周
│       └── 否（周二～周日）→ 不能点「近7天」，会混入本周数据
│           → 必须点「自定义」→ 手动选起止日（如上周一～上周日）
└── 特殊/非标准时间维度
    └── 没有对应快捷按钮 → 点「自定义」
        → 先选开始日期（含开始月份）
        → 再选结束日期（含结束月份）
        → 跨月必须分两次点（先起后止）
```

### 规则详解

#### 1. 月度复盘 → 「自然月」优先
- **入口**：经营概览 / 流量 / 内容分析等模块顶部「统计周期」区域，点「自然月」按钮。
- **弹出月份面板**：点击后弹出 1~12 月宫格（如截图 1 所示）。
- **选月份**：直接点目标月份（如「七月」），周期即变为 `2026-07-01 ～ 2026-07-31`。
- **对比周期**：生意经自动与「上一个自然月」（6 月）对比。
- **适用**：所有月度复盘（月度经营分析、月度投放复盘、月度内容复盘等）。

#### 2. 周复盘 → 周一才用「近7天」
- **仅当今天是周一**时，「近7天」才等价于「上周完整自然周」。
- 例如：8/3（周一）点「近7天」→ 覆盖 7/28(周一) ～ 8/2(周日)，恰好是上周。
- **周二～周日禁止用「近7天」做上周复盘**——会混入本周数据（如周三点近7天包含本周一、二），口径不纯。
- **非周一**做上周复盘：必须走「自定义」，手动选「上周一 ～ 上周日」。
- **任意历史周**（如前两周）：也必须走「自定义」。

#### 3. 特殊时间维度 → 没有快捷按钮就用「自定义」
- 当目标周期不在「昨天 / 近7天 / 近30天 / 自然月 / 今年 / 冲锋日」等预设里时，点「自定义」。
- 典型场景：
  - 跨月周期（如 7/30 ～ 8/2）
  - 非自然月的任意区间（如 7/15 ～ 7/21）
  - 冲锋日等特殊活动日之外的其他自定义活动期
- **操作**：双月面板弹出后，**先点起始日**（注意选对月份），**再点结束日**（跨月时切到另一月面板）。
- **确认**：当前版本 `byted-date` 组件无独立「确认」按钮，第二次点结束日后自动关闭并生效；若未生效，用 React fiber `onClick` 点击日格（详见方法一的 fiber 补充）。

### 自动化要点

- **自然月**：用 `real_click` 点文本为「自然月」的叶子元素，再点月份面板里的目标月份文本。
- **近7天**：仅当 `datetime.now().weekday() == 0`（周一）时才允许点「近7天」做上周复盘；否则弹日历自定义。
- **自定义**：优先按方法一/方法七的 fiber 点击法选日格；若失败按人机补位约定请用户手动设日期。

### 常见错误（agent 曾踩过的坑）

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| 月度复盘用「自定义」逐格选 1~31 号 | 耗时且容易点错 | 用「自然月」一键切 |
| 周二~周日点「近7天」当上周 | 数据混入本周，环比失真 | 非周一必须自定义选上周 |
| 跨月自定义只点一个面板 | 结束日期落到错误月份 | 先起点、再切月点终点 |
| 以为自定义日历有确认按钮 | 第二次点日格后没反应就误判失败 | 当前组件第二次点即生效，必要时 fiber 点击 |

### 与旧方法的衔接

- 方法一的「自定义日历双月面板」仍是本方法第三步的核心技术路径。
- 方法七的「周一近7天=上周」被纳入本决策树的「周复盘 → 是周一」分支。
- 本次新增重点：**月度复盘强制优先「自然月」**、**非周一禁止「近7天」**。
