# Skill 改进指南

详细的改进技巧、检查清单和最佳实践，供 SKILL.md 中引用使用。

---

## 1. Description 优化技巧

Description 是 skill 最重要的元数据，直接影响触发准确性。

### 1.1 好的 Description 特征

- **功能 + 场景 + 关键词**三要素齐全
- 使用第三人称（"本技能用于..."、"当用户...时触发"）
- 包含用户可能使用的各种表达方式（口语、书面语、简称、别名）
- 明确列出触发关键词

### 1.2 Description 模板

```
[技能定位]：[核心功能描述]。当用户[触发场景]时触发。适用场景包括：[场景1]、[场景2]等。关键词包括：[关键词1]、[关键词2]、[关键词3]。
```

### 1.3 常见问题与修复

| 问题 | 示例 | 修复 |
|------|------|------|
| 过于简短 | "Helps with PDFs." | 补充具体功能和使用场景 |
| 缺少触发词 | "处理 PDF 文件的技能" | 添加"PDF、合并、拆分、提取"等关键词 |
| 过于宽泛 | "帮助用户完成各种任务" | 收窄到具体领域和场景 |
| 使用第二人称 | "Use this skill when..." | 改为"当用户...时触发" |

### 1.4 关键词覆盖策略

| 维度 | 说明 | 示例 |
|------|------|------|
| 核心词 | skill 名称的核心概念 | "发票"、"企业" |
| 同义词 | 不同表达方式 | "公司"="企业" |
| 场景词 | 用户的使用场景 | "报销"、"查询" |
| 口语表达 | 用户日常说法 | "帮我看看"、"搞一下" |
| 中英混杂 | 可能的混用场景 | "PDF转Word" |

## 2. 指令结构优化

### 2.1 推荐结构模式

**工作流型**：`概述 → 决策树 → 步骤1 → 步骤2 → ...`
适合有明确先后顺序的流程。

**任务型**：`概述 → 快速开始 → 任务A → 任务B → ...`
适合提供多种独立操作。

**参考指南型**：`概述 → 规范 → 详细说明 → 用法`
适合标准、规范、风格指南。

**能力型**：`概述 → 核心能力 → 1.能力A → 2.能力B → ...`
适合集成系统、多功能平台。

### 2.2 指令清晰度检查

- 每个步骤以动词开头（"执行"、"读取"、"输出"、"判断"）
- 避免模糊表达（"适当处理"→ 具体说明）
- 条件分支明确（"如果 X，则 Y；否则 Z"）
- 有明确的输入/输出说明
- 无矛盾指令

### 2.3 边界处理

- 不适用场景：什么情况下不使用此 skill
- 前置条件：使用前需满足什么条件
- 错误处理：异常情况如何处理
- 输入不足：缺少必要信息时的策略（询问/默认值/跳过）
- 冲突处理：与其他 skill 冲突时如何处理

## 3. 内容精简策略

### 3.1 长度控制

- 目标：SKILL.md ≤ 500 行
- 推荐：200-400 行
- 超过时将详细内容移至 references/

### 3.2 适合移至 references/ 的内容

| 内容类型 | 示例 |
|----------|------|
| 详细 API 参考 | 完整的 API 端点文档 |
| 长篇领域知识 | 行业背景、术语解释 |
| 模板和样式规范 | 排版规范全文 |
| 大量示例 | 超过 3 个以上的详细示例 |

### 3.3 去重原则

- 核心流程/步骤：保留在 SKILL.md
- 详细参考资料：移至 references/
- 不在两处重复相同信息

## 4. 联网搜索改进策略

### 4.1 搜索查询设计

为每个 skill 设计 3-5 个搜索查询：

| 维度 | 查询模板 |
|------|----------|
| Prompt 质量 | `"[skill 功能] prompt engineering best practices"` |
| Agent Skill 模式 | `"AI agent [skill 领域] workflow design"` |
| 错误处理 | `"prompt error handling edge cases [skill 功能]"` |
| 领域前沿 | `"[skill 领域] best practices [当前年份]"` |

### 4.2 结果评估框架

| 评估项 | 分值范围 | 说明 |
|--------|----------|------|
| 适用性 | 1-5 | 与当前 skill 的相关程度 |
| 可实施性 | 1-5 | 能否通过修改 SKILL.md 实现 |
| 风险等级 | 低/中/高 | 引入新问题的可能性 |
| 影响力 | 1-5 | 对 skill 效果的改善幅度 |

### 4.3 分类规则

- 适用性 ≥ 4 且 可实施性 ≥ 4 且 风险低 → **直接采纳**
- 适用性 ≥ 3 且 可实施性 ≥ 3 → **需用户确认**
- 其他 → **过滤不采纳**

### 4.4 与用户交互策略

| 情况 | 策略 |
|------|------|
| 二选一建议 | 列出两个选项让用户选择 |
| 权衡型建议 | 说明利弊让用户决定 |
| 范围型建议 | 提供"最小方案"和"完整方案" |

## 5. BUG 沉淀策略

### 5.1 BUG 分类

| 类别 | 说明 | 典型表现 |
|------|------|----------|
| 触发问题 | description 导致误触发或漏触发 | 该触发时未触发 |
| 指令缺陷 | SKILL.md 中的指令有问题 | 步骤矛盾、逻辑缺失 |
| 边界缺失 | 未处理异常或边界情况 | 特定输入时出错 |
| 示例问题 | 示例不准确或误导 | 示例过时、不具代表性 |
| 资源问题 | 文件引用或组织有问题 | 路径错误、信息冗余 |

### 5.2 修复策略

| BUG 类别 | 推荐修复方式 |
|----------|--------------|
| 触发问题 | 优化 description 关键词和范围 |
| 指令缺陷 | 重写有问题的段落，补充决策树 |
| 边界缺失 | 添加"不适用场景"和异常处理 |
| 示例问题 | 替换或补充真实有代表性的示例 |
| 资源问题 | 修复引用路径、拆分/合并文件 |

### 5.3 预防措施模板

修复 BUG 后，建议在目标 skill 中添加：

```
## 注意事项
- [具体预防措施 1]
- [具体预防措施 2]
```

## 6. 质量检查清单

### Frontmatter
- [ ] `name` 符合命名规范（小写、连字符、1-64 字符）
- [ ] `name` 与目录名一致
- [ ] `description` 在 1024 字符以内
- [ ] `description` 包含功能描述和触发条件
- [ ] `description` 使用第三人称

### SKILL.md 内容
- [ ] 总行数 ≤ 500 行
- [ ] 使用祈使句/动词开头的指令风格
- [ ] 包含清晰的工作流程或步骤
- [ ] 包含条件分支和决策逻辑
- [ ] 包含至少一个具体示例
- [ ] 定义了不适用场景或边界条件
- [ ] 所有文件引用路径正确

### 资源文件
- [ ] references/ 中的文件被正确引用
- [ ] 无孤立文件
- [ ] 无信息重复（SKILL.md 与 references 之间）
