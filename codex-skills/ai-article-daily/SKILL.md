# AI Article Daily - 公众号文章日更助手

## 触发场景

当用户提到以下关键词时触发：
- "公众号文章"、"写公众号"、"今日选题"
- "AI热点"、"热点选题"、"找选题"
- "定时写文章"、"每天写文章"
- 或用户直接要求执行公众号文章创作流程

## 用户画像

- **身份**：AI公众号博主
- **内容方向**：AI工具、教程类（AI绘图、AI视频、AI Agent、AI知识库、AI编程、大模型等）
- **偏好**：容易爆、时效性强的内容
- **文风参考**：https://mp.weixin.qq.com/s/ZaN5BnO9xXOX0vGLFCr2Uw

## 完整SOP流程

### 第一步：搜索AI热点

**目标**：从多个渠道搜集当日AI领域热点

**执行动作**：
1. 使用当前运行时可用的网页搜索工具，优先检索一手来源（官方公告、产品文档、论文或采访），再补充主流媒体和社区讨论。
   - 搜索词：`AI 人工智能 热点 <当前年月日>`
   - 搜索词：`AI绘图 AI视频 AI Agent 新工具 新功能 <当前年份>`
   
2. 搜索大模型相关新闻
   - 搜索词：`OpenAI Claude Gemini 大模型 最新 <当前年份>`
   
3. 搜索AI编程工具动态
   - 搜索词：`AI编程工具 Cursor Copilot <当前年份>`

**输出要求**：
- 整理热点列表，标注来源、发布时间、事件发生时间和一手/二手来源类型
- 去重，保留有价值的信息
- 对未能由至少一条可靠来源支持的说法标为“待核验”，不把它写成事实

---

### 第二步：筛选选题

**目标**：从热点中筛选适合公众号的选题

**筛选标准**：
1. **时效性**：优先选择当日或近2日的新闻
2. **爆款潜力**：
   - 大厂动态（OpenAI、Google、Meta、阿里、腾讯等）
   - 新产品/新功能发布
   - 行业变革性事件
   - 争议性话题
3. **匹配度**：符合用户公众号定位（AI工具、教程类）
4. **可操作性**：有足够资料支撑，能写出深度内容

**输出格式**：

```
## 今日AI热点选题推荐

### 第一梯队：爆款潜力高
1. [选题标题]
   - 爆点：xxx
   - 适合角度：xxx
   - 标签：#xxx #xxx

### 第二梯队：话题性强
...

### 第三梯队：教程/工具类
...
```

🔴 CHECKPOINT：列出选题后，等待用户选择题目；未选定题目时，不开始深度检索或写作。

---

### 第三步：搜集资料

**目标**：针对用户选择的选题，全面搜集资料

**执行动作**：
1. 使用当前运行时可用的网页搜索工具深度检索选题相关内容；对产品或模型能力，优先读取官方发布页、文档、论文或公开演示。
   - 搜索词：`[选题关键词] 详细`
   - 搜索词：`[选题关键词] 技术细节`
   - 搜索词：`[选题关键词] 人物/公司背景`
   
2. 整理资料，包括：
   - 核心信息（时间、人物、事件、数据）
   - 技术细节
   - 行业背景
   - 相关人物/公司介绍
   - 媒体评价

**输出要求**：
- 将资料整理成结构化的 Markdown 文件
- 仅在用户要求保存时，写入当前项目的 `outputs/wechat-article/<YYYY-MM-DD>/[选题关键词]_资料.md`
- 标注信息来源

---

### 第四步：确定写作角度

**目标**：为选题提供多个写作角度供用户选择

**常见角度类型**：

| 角度类型 | 适用场景 | 特点 |
|---------|---------|------|
| 热点新闻型 | 重磅新闻发布 | 时效性强，快速传播 |
| 行业影响型 | 新产品/新功能 | 分析对行业的影响 |
| 人物故事型 | 创始人/公司动态 | 有故事性，易传播 |
| 技术解析型 | 技术突破 | 深度内容，干货感强 |
| 对比测评型 | 多个产品对比 | 互动率高 |
| 应用场景型 | 工具类产品 | 实用性强 |
| 教程干货型 | 新工具发布 | 长尾流量好 |

**输出格式**：

```
## 写作角度选项

### 角度一：[角度名称]
- 核心切入点：xxx
- 标题示例：xxx
- 适合读者：xxx
- 内容框架：
  1. xxx
  2. xxx
  ...

### 角度二：...
```

🔴 CHECKPOINT：列出角度后，等待用户选择或组合；未确认前，不生成完整文章。

---

### 第五步：撰写文章

**目标**：按照用户选择的角度和文风撰写文章

**文风要求**：
1. **参考文风**：仅在用户提供或明确授权使用的样本文本范围内提炼高层风格特征；不要模仿特定作者的独特表达。
2. **核心特点**：
   - 第一人称叙述
   - 口语化、接地气
   - 短句短段落
   - 结构清晰
   - 有个人观点和评价
   - 结尾有互动引导

**格式要求**：
- 不使用Markdown格式（不使用#、**等）
- 不使用双引号
- 不使用不恰当的比喻
- 如需解释，只能用类比，且类比对象必须来自日常生活
- 禁止抽象或情感化比喻

**字数要求**：2500字左右

**输出要求**：
- 先在对话中交付草稿；仅在用户要求保存时，写入 `outputs/wechat-article/<YYYY-MM-DD>/[文章标题].md`

---

### 第六步：生成配图

**目标**：为文章生成合适的配图

**配图类型**：
1. **封面图**：带中文标题，吸引眼球
2. **场景图**：展示文章核心场景
3. **对比图**：展示对比概念
4. **概念图**：解释抽象概念

**配图数量**：4-5张

**生图工具**：
- 个人创作者固定视觉签名的封面：使用 `cover-skill`
- 常规位图配图：使用原生 `imagegen`
- 需要 APIMart 的 2K/4K、明确比例或参考图工作流：使用 `apimart-image-gen`

**生图要求**：
- 避免要求模型生成长篇或精确的中文文字；标题和正文由排版层叠加
- 风格适合公众号文章
- 分辨率：2K
- 宽高比：16:9（封面图）、16:9或4:3（文中配图）

**输出要求**：
- 返回图片URL或本地路径
- 标注每张图片的建议插入位置

---

### 第七步：公众号排版

**目标**：按公众号排版格式输出HTML文件

**排版参考**：用户提供的 CSS、品牌规范或现有 HTML；不要假定某台设备上的绝对文件路径存在。

**排版要点**：
1. **标题系统**：
   - H1：左侧红竖线 + 底部小黑条
   - H2：红色文字 + 底部粗灰线
   - H3：黑色加粗 + 底部细灰线

2. **正文样式**：
   - 重点文字：渐变下划线高亮
   - 引用块：左侧红线
   - 图片：圆角 + 阴影

3. **结构要求**：
   - 封面图在最前
   - 图片后可加图片说明
   - 结尾有互动引导

**输出要求**：
- 仅在用户要求保存时生成 HTML，命名格式：`[文章标题]_公众号排版.html`
- HTML可直接复制到公众号编辑器使用

---

### 第八步：提供标题参考

**目标**：为文章提供多个标题选项

**标题类型**：
1. 热点新闻型
2. 行业影响型
3. 人物故事型
4. 技术突破型
5. 对比反差型
6. 悬念好奇型
7. 利益点型

**输出要求**：
- 每种类型提供2-3个标题
- 标注推荐标题
- 询问用户是否需要用某个标题重新生成HTML

---

## 文件输出规范

用户要求落盘时，统一保存到当前项目的 `outputs/wechat-article/<YYYY-MM-DD>/`。未要求保存时，只在对话中交付内容。

**文件命名规范**：
- 资料文件：`[选题关键词]_资料.md`
- 文章文件：`[文章标题].md`
- 配图文件：`[图片描述]-YYYYMMDD.png`
- HTML文件：`[文章标题]_公众号排版.html`

## 执行检查清单

在执行每个步骤前，确认以下事项：

- [ ] 第一步：已从多个渠道搜索热点
- [ ] 第二步：已按筛选标准整理选题
- [ ] 第三步：已全面搜集资料并保存
- [ ] 第四步：已提供多个写作角度
- [ ] 第五步：已按文风要求撰写文章
- [ ] 第六步：已生成4-5张配图
- [ ] 第七步：已按排版格式输出HTML
- [ ] 第八步：已提供标题参考

## 注意事项

1. **时效性优先**：热点新闻类选题必须在发布当日完成
2. **资料准确性**：所有数据和信息必须标注来源
3. **文风一致性**：严格参考用户历史文章文风
4. **配图质量**：图片必须清晰、适合公众号风格；图片内不承担长文本信息
5. **排版规范**：严格按照CSS样式输出
6. **用户确认**：只在选题、写作角度、发布或定时等不可逆节点等待确认；资料收集和草稿打磨可连续完成

## 错误处理

| 触发条件 | 一线处理 | 仍失败时 |
| --- | --- | --- |
| 搜索不可用或来源不足 | 缩小问题、改用官方来源与可信媒体 | 明确说明证据不足，停止把该事件作为事实推荐 |
| 选题没有足够可靠资料 | 将其降为观察项，并给出备选选题 | 请用户提供资料或更换选题 |
| 生图失败或超时 | 简化画面要求，保留无文字构图 | 交付可复用提示词与插图清单，不虚构图片路径 |
| CSS 或品牌素材缺失 | 使用语义化、内联的基础 HTML | 交付结构稿并标明待用户补充的素材 |
| 用户要求直接发布、定时或模仿特定作者 | 先展示草稿和影响范围 | 未得到明确确认时，不发布、不定时、不进行风格仿写 |
