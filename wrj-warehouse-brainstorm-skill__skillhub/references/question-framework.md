# Question Framework

## Six-Layer Questioning Method (六层提问法)

从需求描述出发，逐层深入挖掘问题：

### Layer 1: 事实层 — "是什么"
- 用户要做什么？
- 系统要实现什么功能？
- 有哪些明确的输入和输出？

### Layer 2: 假设层 — "预设了什么"
- 用户假设了什么前提条件？
- 这些假设有依据吗？
- 哪些假设可能不成立？

### Layer 3: 本质层 — "为什么"
- 用户为什么需要这个？
- 表面问题背后的根本问题是什么？
- 解决了这个问题之后，下一个问题是什么？

### Layer 4: 必要性层 — "不做会怎样"
- 如果不做这个项目，业务/用户会受什么影响？
- 有没有更简单的替代方案？
- 现在做的时机对吗？

### Layer 5: 后果层 — "做了会怎样"
- 做了之后可能引发什么新问题？（二阶效应）
- 对现有系统/流程有什么影响？
- 如果失败，损失是什么？

### Layer 6: 先例层 — "有没有人做过"
- 业界有类似的解决方案吗？
- 开源有没有现成的？
- 过往经验库中有没有相关记录？（检索 exp-pattern-library）

## Question Examples by Project Type

### Web应用项目
- 目标用户是谁？日均活跃预估多少？
- 是否需要支持移动端？响应式还是原生？
- 是否涉及支付/敏感数据？合规要求是什么？
- SEO重要吗？（影响前端框架选择）

### 数据平台项目
- 数据量级多大？日增量多少？
- 实时还是离线？延迟容忍度？
- 数据源有哪些？格式统一吗？
- 谁来用这个平台？技术能力如何？

### 工具/脚本项目
- 使用频率？一次性还是长期使用？
- 谁来维护？技术水平如何？
- 是否需要UI？CLI够用吗？
- 是否需要跟其他系统集成？
